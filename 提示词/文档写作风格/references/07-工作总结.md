# 工作总结

## 0. 适用范围

- 读者：上级、导师、协作方，或未来的自己。
- 用途：汇报产出与影响，沉淀可复用经验，明确下一步。
- 组织轴：结果 → 过程 → 问题 → 下一步。
- 结尾：下阶段计划 + 需要的支持。
- 更新：按周期一次性成文；个人复盘可持续追加。

通用规则见 [01-通用规范](01-通用规范.md)。

## 1. 两种模式

| 模式 | 读者 | 语气 | 重点 | 是否允许第一人称 |
|---|---|---|---|---|
| 对外汇报 | 上级 / 导师 | 克制、结果导向 | 产出、影响、数据、下一步 | 少量 |
| 个人复盘 | 自己 | 可放宽，允许情绪 | 事实、原因、行动、可复用经验 | 允许 |

**共同底线**：结构不放宽；事实、感受、行动要分开；不写流水账。

## 2. 对外汇报

### 骨架

```markdown
# <周期> 工作总结

> **状态**：已定稿
> **版本**：v1.0
> **更新**：2026-11-03
> **周期**：2026-11-01 ~ 2026-11-30
> **角色**：……
> **结论**：一句话概括本期产出

## 1. 核心产出

## 2. 数据与影响

## 3. 问题与解决

## 4. 经验沉淀

## 5. 下阶段计划

## 6. 需要的支持
```

### 槽位

| 槽位 | 含义 | 示例 |
|---|---|---|
| `周期` | 总结覆盖的时间 | 2026-11-01 ~ 2026-11-30 |
| `角色` | 本期承担的职责 | gRPC 上报链路改造负责人 |
| `核心产出` | 交付了什么 | 打通 probe → receiver 直连通道 |
| `数据与影响` | 产出带来的可量化变化 | 上报延迟 P99 从 120ms 降到 45ms |
| `完成事项` | 按优先级列的交付 | 设计、编码、测试、上线 |
| `问题与解决` | 遇到的问题、根因、动作 | 连接数超限未处理；增加错误码分支 |
| `经验沉淀` | 可复用的方法或教训 | 先调研成熟框架，再决定自研 |
| `下阶段计划` | 下一步做什么 | 多实例容灾 |
| `需要的支持` | 需要谁提供什么 | 运维开通 etcd 权限 |

### 规则

- **结果前置**：第一屏给产出和影响，不按时间顺序写日记。
- **用结果描述，不用过程描述**：
  - 不写「参与了 XX」。
  - 写「交付 X，影响 Y，指标 Z」。
- **数据可验证**：给基线、实测值、样本量；没有数据时写清定性影响。
- **问题写根因和动作**：不写「遇到了困难，后来解决了」。
- **经验可复用**：写成「做法 + 适用条件 + 代价」，不写感想。
- **下阶段可执行**：每条有计划、时间、验收标准。
- **不写情绪**：对外汇报不写焦虑、吐槽、自我评价。
- **不写流水账**：不按天罗列；按主题和优先级组织。

### 示例

| 不要写 | 应该写 |
|---|---|
| 参与了 gRPC 上报链路的开发 | 独立完成 probe → receiver 直连链路，覆盖设计、编码、测试、上线 |
| 性能提升明显 | P99 从 120ms 降到 45ms，样本 10k |
| 遇到了一些问题，但都解决了 | 连接数超限未返回错误码；增加 `ResourceExhausted` 分支并补回归用例 |
| 学到了很多 | 沉淀「先调研成熟框架再决定自研」：适用于有成熟实现的通用能力；代价是定制受限 |
| 下个月继续努力 | 下阶段完成多实例容灾，验收标准：2 个 receiver 下线 1 个，上报不中断 |

## 3. 个人复盘

### 骨架

```markdown
# <周期> 个人复盘

> **周期**：2026-11-01 ~ 2026-11-30
> **一句话**：本期最大的变化 / 收获

个人复盘可省略文档状态和版本，但周期和一句话必须保留。

## 1. 事实

## 2. 感受

## 3. 原因

## 4. 行动

## 5. 可复用经验

## 6. 下阶段
```

### 槽位

| 槽位 | 含义 | 示例 |
|---|---|---|
| `事实` | 发生了什么，可核对 | 独立完成链路改造并上线 |
| `感受` | 当时的情绪和判断 | 交付前很焦虑，担心边界情况 |
| `原因` | 为什么会有这个结果 | 前期调研不足，自己手搓浪费了时间 |
| `行动` | 下次具体怎么做 | 先列候选方案，再问导师，再动手 |
| `可复用经验` | 能迁移到其他场景的做法 | 方案选型先问「有没有成熟实现」 |
| `下阶段` | 下一步要改变什么 | 每周留 2h 做技术调研 |

### 规则

- **允许第一人称和情绪**：这是个人复盘，不是对外汇报。
- **事实和感受分开**：先写发生了什么，再写当时怎么想。
- **原因写到可控因素**：不把问题全归因于环境或他人。
- **行动要具体**：写「下次先做 A，再做 B」，不写「以后注意」。
- **经验要可迁移**：写清适用条件和边界。
- **不写流水账**：不按天记录；按主题和影响组织。
- **不自我攻击**：可以写失误，但不写长篇自我否定。
- **不用比喻代替分析**：情绪可以写，原因要具体。

### 与对外汇报的差异

| 维度 | 对外汇报 | 个人复盘 |
|---|---|---|
| 开头 | 核心产出 + 影响 | 一句话概括本期变化 |
| 主体 | 结果、数据、问题、经验 | 事实、感受、原因、行动 |
| 语气 | 克制、客观 | 可主观、可情绪 |
| 数据 | 必须有 | 可以少，但事实要具体 |
| 结尾 | 下阶段计划 + 支持 | 下阶段要改变的行为 |
| 禁忌 | 情绪、吐槽、流水账 | 流水账、空泛自责、无行动 |

## 5. 检查清单

- [ ] 第一屏能看出本期核心产出或最大变化。
- [ ] 对外汇报用结果和影响描述，不是过程流水账。
- [ ] 数据有基线、实测值和样本量；没有数据时写清定性影响。
- [ ] 问题写了根因、动作和结果。
- [ ] 经验写了做法、适用条件、代价。
- [ ] 下阶段计划有目标、验收标准、时间。
- [ ] 对外汇报没有情绪化表达和自我评价。
- [ ] 个人复盘事实、感受、原因、行动分开。
- [ ] 个人复盘没有空泛自责或「以后注意」。
- [ ] 没有按天罗列任务。

## 6. 反面模式

- ❌ 按时间顺序罗列每天做了什么。
- ❌ 只写「参与了」「负责了」，不写产出和影响。
- ❌ 用「学到了很多」「提升明显」代替具体结论。
- ❌ 问题只写「遇到了困难」，不写根因和动作。
- ❌ 经验写成感想，没有适用条件和代价。
- ❌ 下阶段计划是「继续努力」「加强学习」。
- ❌ 对外汇报夹带情绪、吐槽、自我否定。
- ❌ 个人复盘写成情绪宣泄，没有事实和行动。
- ❌ 把总结写成正文复述，没有新增判断。
