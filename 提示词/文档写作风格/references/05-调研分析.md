# 调研分析

## 0. 适用范围

- 读者：做决策的人、评审者、未来的自己。
- 用途：回答一个具体问题，支撑一个技术选型、方案取舍或趋势判断。
- 组织轴：问题 → 结论 → 证据 → 对比 → 边界 → 建议。
- 结尾：建议与下一步，不是资料汇总。
- 更新：一次性快照为主；长期跟踪时改为持续维护并写变更记录。

通用规则见 [01-通用规范](01-通用规范.md)。

## 1. 核心原则

1. **调研不是资料汇编**：所有材料服务于一个决策问题。
2. **结论先行**：第一屏给推荐方案、核心理由和可信度。
3. **证据分级**：实测 > 源码 / 官方文档 > 二手资料 > 个人推断。
4. **事实、推断、观点分离**：不把推断写成事实，不把观点写成结论。
5. **对比维度可测**：每个维度有定义、判定标准和数据来源。
6. **包含基线与不做**：至少比较「保持现状 / 不做」。
7. **写清边界**：结论在什么条件下成立、什么场景不适用。
8. **未验证项显式化**：不知道的写不知道，不猜。

## 2. 文档骨架

```markdown
# <主题> 调研分析

> **状态**：草稿
> **版本**：v1.0
> **更新**：2026-11-03
> **问题**：……
> **结论**：推荐……
> **可信度**：高 / 中 / 低
> **决策截止**：2026-11-10

## 1. 问题与范围

## 2. 结论

## 3. 候选对比

## 4. 证据

## 5. 边界、风险与未验证项

## 6. 建议与下一步
```

### 各节职责

| 节 | 必须回答 | 不写什么 |
|---|---|---|
| 问题与范围 | 要回答什么、不回答什么、按什么维度评估 | 大段背景介绍 |
| 结论 | 推荐什么、为什么、代价和前提 | 把候选再列一遍 |
| 候选对比 | 每个候选在统一维度下的表现 | 只列优点 |
| 证据 | 每个判断的依据、方法、局限 | 无来源的断言 |
| 边界与风险 | 结论何时成立、何时失效 | 泛泛的「有风险」 |
| 建议与下一步 | 现在做什么、还要验证什么 | 全文总结 |

## 3. 槽位词表

| 槽位 | 含义 | 示例 |
|---|---|---|
| `问题` | 本次调研要回答的核心问题 | 上报链路应该继续依赖 GSE 还是直连 gRPC |
| `范围` | 调研覆盖的边界 | 只比较内网部署；不评估公网场景 |
| `非范围` | 明确不回答的问题 | 不比较运维成本 |
| `评估维度` | 用什么标准比较 | 复杂度、性能、可维护性、兼容性、工期 |
| `权重` | 维度的重要程度 | 性能 30%、复杂度 25% |
| `判定标准` | 每个维度怎么打分 | 改动文件数 < 5 为低复杂度 |
| `结论` | 推荐方案 | 推荐 gRPC 直连 |
| `核心理由` | 推荐的三条主要依据 | 改动小、可扩展、可回滚 |
| `代价` | 推荐方案的代价 | 需要理解 resolver 行为 |
| `前提` | 结论成立的条件 | 内网直连、receiver 可访问 |
| `不适用场景` | 结论失效的场景 | 需要跨公网、需要平台托管 |
| `候选` | 参与比较的方案 | 自研 / 框架 / 保持现状 |
| `维度表现` | 候选在每个维度上的结果 | 改动范围：小 / 中 / 大 |
| `证据` | 支撑判断的材料 | 实测数据、源码、官方文档 |
| `来源` | 证据的出处 | 标题、版本、日期、URL |
| `方法` | 证据怎么得到 | 压测、读源码、官方文档 |
| `结果` | 证据说明了什么 | P99 45ms，样本 10k |
| `局限` | 证据的适用范围 | 单机测试，未覆盖集群 |
| `可信度` | 结论整体可信程度 | 高：有实测 + 源码 |
| `未验证项` | 还没确认的事 | 多实例下的一致性 |
| `建议` | 下一步动作 | 先做单实例 PoC，再评估多实例 |

## 4. 评估维度与候选对比

### 维度设计

- 维度数量控制在 3~7 个；超过 7 个时合并或分层。
- 每个维度必须有定义和判定标准，否则删除。
- 权重只在需要综合评分时使用；权重必须说明理由。
- 维度一经确定，对所有候选使用同一套标准。

示例：

| 维度 | 权重 | 判定标准 | 数据来源 |
|---|---|---|---|
| 改动范围 | 25% | 改动文件数、接口变更数 | 代码 diff |
| 性能 | 30% | P99、吞吐、资源占用 | 压测 |
| 可维护性 | 20% | 职责清晰度、依赖数量 | 代码评审 |
| 兼容性 | 15% | 旧配置 / 旧接口是否可用 | 兼容测试 |
| 工期 | 10% | 人日估算 | 排期 |

### 候选对比表

至少包含「保持现状 / 不做」作为基线。

| 维度 | 方案 A | 方案 B | 保持现状 |
|---|---|---|---|
| 改动范围 | 大 | 小 | 无 |
| 性能 | P99 45ms | P99 50ms | P99 120ms |
| 可维护性 | 中 | 高 | 低 |
| 兼容性 | 需迁移 | 兼容 | — |
| 工期 | 10 人日 | 5 人日 | 0 |

规则：

- 单元格写数据或明确判断，不写「较好」「一般」。
- 无法量化的维度给判定标准，如「职责数量 ≤ 3 为高」。
- 对比表后只解释不显然的格子，不复述整张表。
- 单一维度明显胜出时，不必强行加权求和。
- 评分只用于辅助判断，不作为结论唯一依据。

## 5. 证据与来源

### 证据分级

| 级别 | 证据类型 | 使用规则 |
|---|---|---|
| A | 实测：压测、抓包、PoC、日志 | 可直接作为结论依据 |
| B | 源码、配置、接口定义 | 注明版本和路径 |
| C | 官方文档、标准、RFC | 注明版本或发布日期 |
| D | 二手资料：博客、文章、视频 | 只作为线索或观点 |
| E | 个人推断 | 必须标注，不得写成事实 |

### 标注格式

- **事实**：直接陈述，后接来源或数据。
- **推断**：`**推断**：……；依据：……；验证方式：……`。
- **观点**：`**观点**：……；立场：……；适用条件：……`。
- **待验证**：`**待验证**：……；影响：……；计划：……`。

### 来源格式

```markdown
- **来源**：<标题>，<版本 / 日期>，<URL>
- **方法**：<压测 / 读源码 / 官方文档 / PoC>
- **结果**：<关键数据或结论>
- **局限**：<样本、环境、未覆盖场景>
```

规则：

- 不引用没读过的资料。
- 不编造 URL、版本号、论文、benchmark 数据。
- 同一个结论有多个来源时，优先采用更高级别的证据。
- 二手资料与实测冲突时，以实测为准，并说明差异。
- 数据给样本量、时间范围、测量方法；否则标为「参考值」。

## 6. 结论与边界

### 结论写法

```markdown
## 2. 结论

- **推荐**：采用 gRPC 直连通道。
- **核心理由**
  1. 改动范围小：不需要改现有数据结构。
  2. 可扩展：后续多地址场景可直接加 resolver。
  3. 可回滚：配置切回 GSE 即可。
- **代价**
  1. 需要理解 resolver / balancer 行为。
  2. 单 receiver 场景仍有单点。
- **前提**
  - 内网直连，receiver 地址可达。
- **不适用场景**
  - 需要跨公网或平台托管路由。
- **可信度**：高（有 PoC + 源码依据）。
```

规则：

- 推荐方案只能有一个；需要组合时说明主次。
- 核心理由控制在 3 条以内；超过 3 条说明重点不清。
- 代价和前提必须写；没有代价的推荐视为不完整。
- 可信度用「高 / 中 / 低」，并给依据。
- 不写「综合来看」「各有优劣」这类无结论的话。

### 边界写法

- **成立条件**：结论依赖哪些前提。
- **不适用场景**：哪些情况下结论失效。
- **风险**：采用后会引入什么新问题。
- **未验证项**：还没确认的事，以及如果错了会怎样。

## 7. 未验证项与下一步

未验证项用表格：

| 项 | 影响 | 验证方式 | 截止 | 负责人 |
|---|---|---|---|---|
| 多实例下的一致性 | 可能导致数据重复 | 起 2 个 receiver 压测 | 2026-11-15 | 自己 |
| 连接数上限 | 高并发下可能拒绝连接 | 逐步加压到配置上限 | 2026-11-12 | 自己 |

下一步建议：

1. 先做最小 PoC，验证核心假设。
2. 再补对比维度的实测数据。
3. 最后给正式推荐和决策截止日期。

规则：

- 建议按优先级排序，不写「继续调研」。
- 每条建议有可执行的下一步和负责人。
- 决策截止日期明确；到期未决时给默认决策。

## 9. 检查清单

- [ ] 第一屏能回答：问题、结论、推荐、可信度。
- [ ] 结论只有一个推荐方案，核心理由不超过 3 条。
- [ ] 写了代价、前提和不适用场景。
- [ ] 对比表至少包含「保持现状 / 不做」。
- [ ] 每个评估维度有定义、判定标准和数据来源。
- [ ] 每个判断都有来源，或明确标为推断 / 观点。
- [ ] 事实、推断、观点没有混写。
- [ ] 数据给了样本量、时间范围和测量方法。
- [ ] 未验证项有影响、验证方式、截止和负责人。
- [ ] 没有把资料摘要当调研，没有堆砌无来源的断言。
- [ ] 结尾是建议与下一步，不是全文总结。

## 10. 反面模式

- ❌ 先有结论，再找证据。
- ❌ 只列优点，不列代价和风险。
- ❌ 对比维度不可测，全是「好 / 一般 / 差」。
- ❌ 没有基线，只比较候选方案。
- ❌ 来源不可追溯，只有「网上说」「官方推荐」。
- ❌ 把二手资料当事实，把推断写进结论。
- ❌ 用「业界最佳实践」代替证据。
- ❌ 评分权重没有理由，制造虚假精确。
- ❌ 结论写「各有优劣」，不给推荐。
- ❌ 把调研写成资料汇编或文章摘要。
- ❌ 未验证项不写，默认「应该没问题」。
