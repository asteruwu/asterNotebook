# 注释

## 0. 原则

1. **默认不写**：很多函数不需要注释。
2. **需要时一句话**：简单说明函数做什么。
3. **行内注释尽量避免**：能用命名或结构表达，就不写注释。
4. **不写设计意图**：为什么选这个方案、为什么不选另一个，放到设计文档或提交信息。

## 1. 什么时候写

- 导出函数、类型、常量、错误，名字不足以说明用途时，写一句。
- 代码读不出某个关键语义或约束时，写一句。
- TODO 写一行，说明做什么和解除条件。

## 2. 什么时候不写

- 函数名已经说明用途。
- 内部辅助函数、简单包装、getter / setter。
- 控制流：`// 直接返回`、`// 先校验再处理`、`// 如果 err 不为 nil`。
- 没做什么：`// 不写存储`、`// 不处理远端关闭`。
- 逐行解释：`// 循环 items`、`// 判断为空`。
- 设计意图、方案取舍、历史背景、未来规划。
- 编号步骤注释；把步骤抽成命名函数，名字就是注释。

## 3. 写法

- 一行，简单句。
- 导出函数以函数名开头：

  ```go
  // Get 返回指定用户的当前配置。
  func Get(userID string) (*Config, error)
  ```

- 类型、字段、常量、错误各一句：

  ```go
  // Pool 管理空闲连接和借出连接。
  type Pool struct{}

  // DefaultTimeout 是单次请求的默认超时时间。
  const DefaultTimeout = 30 * time.Second

  // ErrNotFound 表示目标记录不存在。
  var ErrNotFound = errors.New("service: not found")
  ```

- 不写多段，不写列表，不写背景。
- 超过一行，优先删掉或改代码结构。

## 4. 行内注释

默认不写。

只有在命名和代码结构都无法表达某个约束时，才写一行，例如：

```go
// 调用方必须已持有 p.mu。
func (p *Pool) removeLocked(w *waiter)
```

- 不超过一行。
- 不写编号步骤；把每个步骤抽成命名函数。
- 不写「为什么这样设计」。
- 能通过改函数名、拆函数、提前返回表达的，都不写注释。

## 5. 反例

```go
// 校验失败时直接返回，不写存储。
if err := validate(req); err != nil {
    return err
}
```

删掉。代码已经说明。

```go
// 如果 err 不为 nil，直接返回。
```

删掉。复述代码。

```go
// 这里之所以用 channel 而不是 mutex，是因为……
```

删掉。设计意图放设计文档。

```go
// 本来可以实现多实例，但这次没做。
```

删掉。没做什么不需要写在代码里。

```go
// 0. 参数校验
// 1. 幂等检查
// 2. 加载聚合
```

删掉。把三步抽成命名函数，调用顺序本身就是注释。

## 6. 检查清单

- [ ] 能删的注释已删；大多数函数没有注释。
- [ ] 保留的注释只有一句，说明函数功能或非显然语义。
- [ ] 没有行内注释；没有编号步骤注释。
- [ ] 没有控制流复述、没做什么、设计意图、方案取舍。
- [ ] TODO 只有一行，写做什么和解除条件。
- [ ] 注释与代码同步，没有过时注释或注释掉的代码。
