# 包结构与错误常量

## 1. 包分层

```text
project/
├── cmd/                 入口，唯一接线点
├── internal/
│   ├── transport/       协议接入：HTTP、gRPC、CLI
│   ├── service/         用例编排、业务规则
│   ├── repository/      存储访问
│   └── model/           领域模型，叶子包
├── pkg/
│   ├── errors/          哨兵错误，按域分组
│   ├── constant/        共享常量，按域分组
│   └── tools/           无业务依赖的工具
├── configs/             配置样例
└── integration/         端到端测试
```

### 依赖方向

```text
cmd
 ├── transport ──> service
 ├── service   ──> repository
 └── repository ──> model

pkg/* ──> 标准库 + 少量基础依赖
```

规则：

- 入口只依赖顶层模块；顶层模块之间通过接口或函数值协作，不互相 import。
- `service` 定义它需要的接口，`repository` 提供实现；接口在消费方。
- `model` 是叶子包，被多个包共享，自己零项目依赖。
- `pkg/errors`、`pkg/constant`、`pkg/tools` 是叶子工具包，不 import 业务包。
- 依赖只能向下：`cmd → transport/service/repository → model → pkg/*`；出现反向依赖就重新设计边界。

### 导入与别名

- 分组顺序：标准库 → 第三方 → 本项目；组间空行。
- 本项目包别名固定，例如 `gerrors`、`gconst`；同一项目内不要换别名。
- 别名只在解决重名或缩短长路径时使用，不为每个包都起别名。
- `gofmt` 不负责分组；提交前人工检查。

## 2. 入口只接线

入口只做三件事：

1. 读配置、构建运行时对象。
2. 按依赖逆序构造模块并接线。
3. 启动服务、等待退出信号、统一回收。

```go
func run() error {
    cfg, err := buildConfig()
    if err != nil {
        return err
    }

    app, err := initComponents(cfg)
    if err != nil {
        return err
    }
    defer func() {
        if err := app.Close(); err != nil {
            log.Printf("[main]failed to close app: %s", err.Error())
        }
    }()

    return serve(app)
}
```

规则：

- 构造顺序按依赖逆序：先存储，再服务，最后接入层。
- 模块之间不互相 new；由入口把上游接口或函数值传给下游。
- 失败路径也要回收已创建资源。
- 入口只打印顶层错误并退出；模块内部不 `os.Exit`。
- 启动、监听、退出信号处理留在入口或专门的 `serve` 函数里。

## 3. 接口与注入

### 接口定义在消费方

```go
// Repository 提供实体读写。
type Repository interface {
    FindByID(ctx context.Context, id string) (*Entity, error)
    Save(ctx context.Context, entity *Entity) error
}

// Handler 处理请求。
type Handler interface {
    Handle(ctx context.Context, req Request) (Response, error)
}

// Notifier 发送事件通知。
type Notifier interface {
    Notify(ctx context.Context, event Event) error
}
```

规则：

- 接口放在使用它的包，而不是实现它的包。
- 接口只包含调用方真正需要的方法；不要提前为未来加方法。
- 接口用能力名词命名：`Repository`、`Notifier`、`Handler`、`Gateway`。
- 不加 `I` 前缀，不加 `Interface` 后缀。
- 构造函数返回具体类型；调用方接收接口。

### 依赖注入

跨层协作用接口或函数值，不引入全局单例：

```go
func NewService(repo Repository, notifier Notifier, now func() time.Time) *Service {
    return &Service{repo: repo, notifier: notifier, now: now}
}
```

```go
func NewServer(handler func(context.Context, Request) (Response, error)) *Server
```

规则：

- 依赖从构造函数传入，模块内部不查找全局单例。
- 需要多个方法时用接口；只需要一个回调时用函数值。
- 时间、随机数、ID 生成器等外部性依赖用函数值注入，方便测试。
- 回调签名要能表达错误和资源释放。

## 4. 配置分层

配置分三层，每层职责不同：

| 层 | 类型 | 特征 | 位置 |
|---|---|---|---|
| 原始配置 | `RawConfig` | 带 `yaml` / `json` tag，字段贴近配置文件 | `configs` 或 `internal/config` |
| 校验后配置 | `Config` | 已补默认值、已校验、类型安全 | `internal/config` |
| 运行时对象 | `Runtime` / `App` | 已完成依赖装配，可直接使用 | `internal/app` |

构建流程：

```text
Load → Validate → BuildPlan → ValidateRuntime → Assemble
```

规则：

- `Load` 只读文件、反序列化，不做校验。
- `Validate` 校验必填、格式、唯一性、范围。
- `BuildPlan` 做派生，不校验、不装配。
- `ValidateRuntime` 校验派生后的语义一致性。
- `Assemble` 只装配运行时对象，不再读配置。
- 每个阶段只做一件事；阶段名就是函数名。
- 新增阶段时先改编排函数，再写阶段函数。

### 默认值与校验

- 默认值在一个函数里统一应用，例如 `withDefaults`。
- 校验分两个阶段：原始配置（声明是否合法）和运行时（语义是否一致）。
- 校验错误聚合返回，不遇到第一个错误就退出。
- 配置错误统一包装成 `ErrInvalidConfig`，并带阶段名。

## 5. pkg/tools

`pkg/tools` 只放「与业务无关、可独立复用、无状态」的工具；优先纯函数，允许通用 I/O 包装。

适合放：

- 字符串 / 切片 / map 处理：`UniqueStrings`、`StringsOverlap`、`CloneOrDefault`。
- 类型转换：`ToInt`、`ToUnixTime`、`ToStrings`、`ToStringField`。
- 通用 I/O 包装：`LoadYAML`、`ReadJSON`。
- 泛型算法：去重、分组、排序、复制。

不适合放：

- 带业务类型的函数：`BuildOrder`、`ValidatePayment`。
- 依赖项目配置的函数：`NewPool`、`NewService`。
- 只被一个包使用的私有逻辑。
- 有业务逻辑、有状态、依赖全局变量，或只被一个包使用的 I/O 逻辑。

规则：

- `pkg/tools` 不 import 任何业务包。
- 优先纯函数：输入决定输出；通用 I/O 包装可以存在，但不得包含业务逻辑。
- 不读环境变量，不写日志，不持有全局状态。
- 泛型优先：`DuplicateStrings[T ~string]`、`CloneOrDefault[T any]`。
- 命名具体：`UniqueStrings` 而不是 `Dedup`；`ToStringsLenient` 而不是 `Convert`。
- 每个工具函数配单元测试；边界条件写清楚。
- 一旦函数需要业务类型，就把它移回业务包，不要为了复用硬塞进 tools。

## 6. pkg/errors

### 按域分组

```go
// config errors
var (
    ErrInvalidConfig = errors.New("config: invalid")
    ErrMissingField  = errors.New("config: missing required field")
)

// transport errors
var (
    ErrUnauthorized = errors.New("transport: unauthorized")
    ErrForbidden    = errors.New("transport: forbidden")
    ErrRateLimited  = errors.New("transport: rate limited")
)

// service errors
var (
    ErrNotFound  = errors.New("service: not found")
    ErrConflict  = errors.New("service: conflict")
    ErrUnavailable = errors.New("service: unavailable")
)

// repository errors
var (
    ErrQueryFailed = errors.New("repository: query failed")
    ErrWriteFailed = errors.New("repository: write failed")
)
```

规则：

- 按层 / 域分组，组间空行，组前写注释。
- 每个哨兵错误写一句注释，说明「什么时候出现」。
- 错误文本前缀用域名：`config:`、`transport:`、`service:`、`repository:`。
- 错误文本小写，不加句号，不写变量值。
- 不把具体参数写进哨兵错误；参数用包装时的上下文补充。

### 包装与聚合

```go
return fmt.Errorf("%w: %s", gerrors.ErrInvalidConfig, detail)
```

```go
errs := append(repoErrs, handlerErrs...)
if len(errs) > 0 {
    return nil, fmt.Errorf("assemble: %w", errors.Join(errs...))
}
```

规则：

- 包装必须用 `%w`，保留错误链。
- 聚合多个错误用 `errors.Join`。
- 校验阶段收集全部错误，不 fail-fast。
- 判断错误用 `errors.Is` / `errors.As`，不比较字符串。
- 不要在每一层都 `log` 再返回；在边界记录一次。
- 预期错误不 `panic`；只在连接边界 `recover`，并记录堆栈。

### 边界映射

对外状态码映射集中在一个函数：

```go
func WriteError(w http.ResponseWriter, err error) {
    status := http.StatusInternalServerError
    switch {
    case errors.Is(err, gerrors.ErrUnauthorized):
        status = http.StatusUnauthorized
    case errors.Is(err, gerrors.ErrForbidden):
        status = http.StatusForbidden
    case errors.Is(err, gerrors.ErrNotFound):
        status = http.StatusNotFound
    case errors.Is(err, gerrors.ErrConflict):
        status = http.StatusConflict
    case errors.Is(err, gerrors.ErrRateLimited):
        status = http.StatusTooManyRequests
    case errors.Is(err, gerrors.ErrUnavailable):
        status = http.StatusServiceUnavailable
    }
    http.Error(w, http.StatusText(status), status)
}
```

规则：

- 一个错误只在一个地方映射成对外状态码。
- 接入层可以返回「部分响应 + 错误」，由边界函数补全。
- 对客户端只暴露状态文案，不暴露内部错误细节。
- 安全相关失败默认 fail-closed：认证缺失、策略缺失、权限不足都拒绝。

## 7. pkg/constant

### 按域分组

```go
// ===== service =====

const DefaultTimeout = 30 * time.Second
const DefaultPageSize = 20
const MaxRetries = 3

// ===== transport =====

const DefaultReadLimit = 1 << 20
const DefaultWriteTimeout = 10 * time.Second

// ===== repository =====

const DefaultPoolSize = 16
const DefaultIdleTimeout = 60 * time.Second
```

规则：

- 按域分组，段注释统一。
- 默认值用 `DefaultXxx`。
- 上下限用 `XxxMin` / `XxxMax`。
- 枚举用类型化常量：

  ```go
  type Role string

  const (
      RoleAdmin Role = "admin"
      RoleUser  Role = "user"
  )
  ```

- 常量只依赖标准库，不依赖业务类型。
- 文件内专用常量放在文件顶部。
- 默认值集中应用，不散落在构造函数里。
- 禁止魔法数字和魔法字符串；同一个值只定义一次。

### 常量放哪里

| 范围 | 位置 |
|---|---|
| 跨包共享、与业务无关 | `pkg/constant` |
| 某个包内共享 | 该包的 `constant.go` 或文件顶部 |
| 单个函数内使用 | 函数内 `const`，并命名 |
| 配置默认值 | `pkg/constant`，由 `withXxxDefaults` 应用 |

## 8. 日志

日志是边界行为，不是流程注释。

- 统一用 `log`，不用 `fmt.Println` 打生产日志。
- 每条日志带组件前缀：`[main]`、`[http]`、`[service]`、`[repo]`。
- 消息小写，不加句号；错误用 `errmsg: %s` 或 `: %v` 附在末尾。
- 初始化失败记录「组件 + 配置项 + 类型」，再返回包装错误。
- 请求级错误在边界记录一次，不在每一层重复 log-and-return。
- 不记录敏感信息：token、密钥、完整请求体、`Authorization` 头。
- 连接级 panic 必须记录堆栈，但不影响其他连接。
- 高频路径避免每请求一条 info 日志；需要统计用指标，不用日志。
- 日志字段顺序固定：组件 → 动作 → 对象 → 错误。

示例：

```go
log.Printf("[service]failed to initialize order service: %s", err.Error())
log.Printf("[http]panic while serving %s: %v\n%s", remoteAddr, r, debug.Stack())
```

## 9. 反模式

- ❌ 顶层模块互相 import，靠包级变量共享状态。
- ❌ 入口里写业务逻辑，或模块里自己读配置。
- ❌ 接口定义在实现方，接口包含一堆用不到的方法。
- ❌ `pkg/tools` import 业务包，或包含有状态函数。
- ❌ 业务代码里散落 `errors.New`。
- ❌ `fmt.Errorf` 包装时用 `%v` 而不是 `%w`。
- ❌ 用字符串比较判断错误类型。
- ❌ 每一层都 log 同一个错误。
- ❌ 错误文本大写、带句号、包含敏感参数。
- ❌ 魔法数字、重复默认值、常量散落。
- ❌ 原始配置、校验后配置、运行时对象混成一个结构体。
- ❌ 生产日志用 `fmt.Println`，或没有组件前缀。
- ❌ 日志里打印 token、密钥、完整请求体。

## 10. 检查清单

- [ ] 顶层模块之间没有互相 import。
- [ ] 入口是唯一接线点，构造顺序按依赖逆序。
- [ ] 接口定义在消费方，方法数量最小。
- [ ] 跨层协作用接口或函数值注入，没有全局单例。
- [ ] 配置按「原始 → 校验后 → 运行时」分层。
- [ ] 装配函数只装配，不做语义校验。
- [ ] `pkg/tools` 没有业务依赖；函数优先纯函数，允许通用 I/O 包装。
- [ ] 错误集中在 `pkg/errors`，按域分组并写注释。
- [ ] 错误包装用 `%w`，聚合用 `errors.Join`。
- [ ] 对外状态码映射集中在一个函数。
- [ ] 常量集中在 `pkg/constant` 或文件顶部，没有魔法值。
- [ ] 默认值集中应用，没有重复定义。
- [ ] 日志带组件前缀，用 `log` 而不是 `fmt.Println`。
- [ ] 请求级错误只在边界记录一次，没有重复 log-and-return。
- [ ] 日志没有敏感信息。
