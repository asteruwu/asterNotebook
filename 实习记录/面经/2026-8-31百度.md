6. 介绍 GMP 调度模型

   g -> goroutine，m -> goroutine 管理器，p -> 队列
   m 绑定一个 p，从 p 里面取出 g 来执行；m 空闲时可以偷取其他 m 的 g，也可以从全局 p 里面拿 g

34. 就相当于已经封装好了。那有用过 redis 吗？怎么用的？

    redis stream，类似于一个消息队列

35. stream 和消息队列有什么联系吗？具体怎么用的？

    因为我自己项目会涉及到 redis 和 mysql 的数据一致性，用 redis 在 mysql 前面去扛住大部分流量。要确保 redis 的库存扣减最后有真正落库到 mysql，就需要用到 stream，消费完数据需要 ack，确保可靠消费。所以在 redis 扣减库存的时候会往 stream 里面再写一条库存扣减记录，后续再用另外的 worker 从 stream 里面取出记录，写到 mysql

36. 那为什么要用 stream 做消息队列不用 list？

    因为要用到 ack，下游消费者消费完必须发一个 ack，redis 才会把记录更新为已消费，但 list 就没法实现这个效果

37. 这个 ack 是自己实现的还是 redis 自己的功能？

    redis 自己的功能，类似于 kafka，下游写完也得回一个 ack

38. 那你是怎么解决这个 redis 和数据库的一致性问题的？

    我们无非就是担心 redis 里有扣减，这部分数据没有同步到数据库；或者 redis 宕机，数据全部丢失

    因为我这里考虑的场景是流量比较大，很高的并发，可能好几万 qps，mysql 可能会扛不住，所以才选择把 redis 放在前面

43. 那他们会不会丢失数据？

44. 那一般生产环境怎么用？你自己的是怎么用？

    aof 每秒写，可接受一秒的数据丢失

45. 那这样 aof 不会很慢吗，假如说有一百万条日志，还得去一条一条重放？
